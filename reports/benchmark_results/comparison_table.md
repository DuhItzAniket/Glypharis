# Comparison table

Generated by `scripts/experiment_comparison.py` from `reports/external/results.json`, `reports/baselines/results.json`, `reports/efficiency/phase16/results.json` and `reports/benchmark_results/efficiency_comparison.json`; do not edit by hand. The same rows are in `comparison_table.csv`.

**Latency is measured on HierText validation, in different sittings (Phase 5 for the baselines, Phase 16 for GLYPHARIS), so no latency difference may be stated from this table.** A model's latency is the same on every row: it was not measured on that row's dataset.

- A cell is `n/a` when these sources hold no value for it. Nothing is estimated.
- Accuracy values are percentages with a 95% bootstrap interval. Intervals are over lines in the recognition table (words for IIIT5K) and over pages in the end-to-end table.
- The track is strict unless the Track column says otherwise. On IIIT5K the alphanumeric row is the headline, because the strict track charges case against upper-case labels.
- GLYPHARIS accuracy comes from the strict fp32 evaluation on the GPU. Its latency in the first two tables is the PyTorch, CPU, 10 threads profile of v1's default backend, so the two numbers are from different runs.
- On HierText validation the baselines were scored on 10,000 lines and 400 pages, and GLYPHARIS on 74,500 lines and 1,715 pages. The baselines' counts are seeded subsamples, so those rows are not directly comparable with the GLYPHARIS rows.
- GDC-scan is one document: a case study whose intervals are conditional on it.
- On OmniDocBench the reference unit is a layout block, so bag-of-lines CER and both F1 values are `n/a`. Its order-aware CER is this project's metric, not the official protocol.
- The sources give no parameter count for the baselines. VRAM exists only for the GLYPHARIS GPU runs in the last table; every latency in the first two tables is a CPU run.
